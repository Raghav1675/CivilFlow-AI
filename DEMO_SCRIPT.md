# CivicFlow demo walkthrough (100–120 seconds)

## 0:00–0:12 — Overview
“CivicFlow is an operations workspace for turning citizen reports into accountable civic work orders. This map uses illustrative sector-level locations, and the preloaded records are synthetic—not a live municipal feed.”

## 0:12–0:32 — Submit a report
Open **New report** and enter:

> A public bin is overflowing beside a pedestrian crossing and waste is spreading onto the walkway.

Choose **Sector 17** and an estimated affected population. Attach a suitable sample photo if available. Click **Analyse and prepare draft**.

Say whether you are using **Demo rules** or a configured Google AI model. Do not describe keyword rules as AI inference.

## 0:32–0:48 — Review the triage
Show the suggested category, department, severity and recommended first action. If candidate related reports appear, explain that they are potential matches to review—not confirmed duplicates. Click **Create work order and add to queue**.

## 0:48–1:05 — Dispatch the work
In **Dispatch**, choose the new work order, assign a team and set it to Assigned. Show the interactive Leaflet map and sector run sheet. Clarify that stop grouping is not a real traffic-optimized route and gives no live ETA.

## 1:05–1:20 — Work register
Open **Incidents**. Demonstrate search/status/severity filters, editing ownership, and CSV export. This makes the prototype useful as an operations workflow rather than just a chat interface.

## 1:20–1:38 — Closure evidence
Open **Verify closure**. If the case has a before photo, upload a completion photo and run comparison only if an API model is configured. Explain that the app requires a human reviewer to approve closure; demo mode explicitly requires manual review.

## 1:38–1:50 — Insights / close
Show departmental workload and severity mix. Close with: “CivicFlow is designed as a reusable civic incident layer. A live city pilot would need authorized municipal integration, verified street-level coordinates, audit controls and evaluation with civic staff.”

## Recording reminders

- Record the actual running app, not a mockup.
- Keep your API key out of screen recordings and browser history.
- Do not claim official integrations, live city statistics, GPS accuracy, route optimization or model confidence that the prototype does not provide.
